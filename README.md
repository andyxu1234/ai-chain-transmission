# 🔗 AI 产业链 美股 → A股 传导日报

> 每个交易日盘前（北京时间 09:00）自动生成：把隔夜美股的涨跌，按 **8 大产业链环节** 拆解成 A股/港股同环节的传导预判，并附 AI 机制归因。

## 🎯 它回答什么问题

不是"美股涨 A股就涨"这种废话，而是：

- **隔夜美股哪个环节在动？** 拆成 8 个环节分别看，而不是笼统看"AI 板块"
- **A股同环节历史上跟涨/跟跌多少？** 用滚动 20 日回归算出的传导系数 β，并给出 R² 可信度
- **今天的传导信号是强是弱？** 分强/中/弱/失效四档，而非无条件预测
- **哪些标的值得盯？** 环节内按历史跟随意愿（ρ）排序
- **为什么传导成/不成？** AI 归因把 R²、锚点离散度、个股 ρ 与隔夜新闻串成机制解释
- **昨天猜对了没有？** T+1 实测验证，命中率逐日累积

## 🧮 方法论

**传导系数 β** —— 对每个环节，取最近 20 个配对交易日：

```
x = 美股该环节当日加权涨跌（隔夜）
y = A股该环节次日涨跌 − 沪深300次日涨跌（超额，剥离大盘）
β = OLS(x, y) 斜率      R² = 可信度
```

强度分四档：**强**（R² ≥ 0.35）/ **中**（≥ 0.15）/ **弱**（≥ 0.05）/ **失效**（< 0.05）。

三个必须处理的失真：

| 失真 | 后果 | 处理 |
|---|---|---|
| **未收盘占位行** | 接口在当前市场未收盘时会返回上一交易日副本（OHLC 四值完全相同），不剔除会导致中美串日、β 全错 | 检测 OHLC 四值与前一行完全相同的记录并丢弃 |
| **中美假期错位** | 简单按"上一日"配对会错位，长假后多个美股日无法对应 | 美股 D 日映射到 D 之后第一个 A股交易日（`bisect_right`），长假后多个美股日累积到同一 A股日 |
| **大盘污染** | A股环节涨跌主要跟着沪深300走，测出的是"大盘同步性"而非产业链传导 | y 先减去同期沪深300涨跌，做超额收益回归 |

**T+1 验证（walk-forward）** —— 只用 T−1 及之前的样本拟合 β 去预测 T 日，再对照 T 日实际超额。
这是唯一诚实的口径；若用含 T 日的数据拟合再预测 T 日，命中率会虚高。

**AI 归因解读** —— `engine.py` 负责事实（涨跌幅、β、R²、离散度、ρ、命中与否），
`attrib.py` 只负责解释（为什么传导强/失效、昨日偏差说明什么、哪个点最反直觉）。
归因调用失败时自动降级，日报照常生成，只是少一段解读。

## 🗂️ 数据来源

行情数据来自 **westock CLI**（腾讯自选股数据接口）：

- `kline` — 日线序列（β 滚动回归的唯一输入）
- `quote` — 指定日行情（美股指数走这条，因为 kline 不支持美股指数）
- `news` — 各环节波动最大的美股锚点的隔夜消息
- `market-overview` — A股市场情绪画像

LLM 归因走 OpenAI 兼容接口，按 `deepseek > qwen > openai > siliconflow` 顺序自动选择可用凭证。

不编造数据：接口未返回的字段显示"—"。

## 🧱 代码结构

| 文件 | 职责 |
|---|---|
| `chain-map.json` | 中美标的映射与权重（**人工维护**，改动会让历史 β 失去可比性） |
| `ws.py` | westock CLI 封装（子进程 + 显式 utf-8 解码） |
| `engine.py` | 采集 → 交易日配对 → β 滚动回归 → 信号 → walk-forward 验证 → 落盘 |
| `attrib.py` | AI 归因解读（调用 LLM，失败自动降级） |
| `render.py` | 单文件 HTML 渲染（零外部依赖、零 JS 依赖） |
| `publish.py` | GitHub Git Data API 发布（`git push` 走代理不可用时的通道） |
| `run_daily.py` | 每日编排：交易日判断 → 采集 → 归因 → 渲染 → 发布 |

**为什么发布走 API 而不是 `git push`**：本机 `git push` 经 HTTP 代理实测频繁报
`schannel: server closed abruptly` / `CONNECT tunnel failed 502`，而 `api.github.com` 更稳定。
`publish.py` 的核心约定是 **远端 tree 与本地区 tree 逐字节一致**（tree sha 可被 API 精确复现），
本地分支则指向远端产出的 commit sha，因此本地与远端头部永远一致、无 ahead/behind。
内部有三条硬断言：不用 `base_tree`（否则删除传不出去）、blob 从 git 对象库取（不读工作区）、
tree 不一致时绝不改 ref（否则本地会指向缺失对象）。

## 🛠️ 本地运行

```bash
# 交易日盘前跑一次（周末与无新数据时自动跳过）
python run_daily.py

# 强制重跑（忽略跳过判断）
python run_daily.py --force

# 只跑采集与计算，不调 LLM
python run_daily.py --no-ai
```

需要：`westock.exe`、`GITHUB_TOKEN`、以及仓库根 `.env` 里的 LLM key（见 `.env.example`）。
`.env` 已在 `.gitignore` 中，不会被提交。
